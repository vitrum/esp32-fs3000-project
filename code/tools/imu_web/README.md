# 双 IMU HTTP 三维回放

## 三个方案

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| HTTP + Matplotlib Agg 按需 PNG（旧方案） | 真实 Matplotlib 三维图，不依赖 CDN，快速实现，视角可改 | 服务端逐帧渲染 |
| Matplotlib Animation 导出视频 | 播放流畅、便于分享 | 预生成耗时，需要视频编码器，视角固定 |
| **Python 分析 + Three.js（当前实现）** | 客户端 WebGL、高帧率、鼠标旋转，无逐帧网络请求 | 浏览器需要 WebGL2 |

当前使用第三种方案。Python 共享估计逻辑不变，浏览器一次获取全部姿态，
通过 Three.js 本地渲染，不再轮询 PNG。支持暂停、逐样本拖动、倍速、
鼠标旋转/缩放/平移、仰角/方位角和安装坐标调整、全量 JSON 下载。

## 座舱、正北参考和手臂运动

- 1 个 Three.js 世界单位 = 1 cm。世界坐标 X 为参考北、Y 为西、Z 向上；
  车身局部 X 向前、Y 向左、Z 向上。
- 按用户提供尺寸绘制 **中对中 38 cm 公路弯把、码表相对把横前伸 8 cm**，
  包括左右手变头、右侧电变手变头握持参考点、刹车杆和码表架。
  8 cm 解释为码表中心到把横中心的水平前伸，不是外壳间隙。
  弯把 reach 约 8 cm、drop 约 12 cm、管径和手变头形状均为估计。
- 码表估计尺寸为 **8 × 5 × 2 cm**，前臂为 **26 × 8 × 6 cm**，
  都是长 × 宽 × 厚。两个长方体共用同一尺度，初始长轴为 +X。
- 码表含示意屏幕；前臂长方体表示佩戴 WT901 的前臂段，不是 WT901 本体大小。
  长方体与传感器三轴一起旋转，尺寸并非用户实测。
- 前臂远端绘制腕带、估计尺寸 2.5 × 1.8 × 0.6 cm 的 IMU 和手掌，
  穿戴设备三轴箭头随腕部位置移动，不再从固定前臂中心发出。
- 黄色大箭头为**固定水平参考磁北 N（未校准）**；青色箭头为随码表变化的车头方向。
  两者不能混为一谈，车辆转弯时只有后者跟随转动。地面网格每格 10 cm。
- CSV 没有磁场三轴或校准状态，无法证明设备 yaw=0 就是地磁北。
  按用户选择使用人工初始航向（0 北、90 东），不把它标作实测磁航向。
  未经测量的默认初始角 0° 只是参考，不是自动对北。
- 码表、码表架、车把、手变头共用座舱姿态。前臂姿态仍来自其自身传感器，
  不再将码表转角重复叠加到前臂上；其位置相对座舱约束求解：
  - **默认手变头支撑**：右手掌固定在右手变头参考握持点，前臂中心、腕部 IMU、
    肘部随相对姿态运动。掌心约束并不意味着腕带传感器原点固定。
  - **离把活动**：初始估计肘部固定在车身坐标，26 cm 前臂杆驱动腕部移动，
    90° 动作可让腕部相对移动约 36.8 cm，不增加虚假的角度放大。
  - 用 `Q_board^-1 * Q_arm` 在车身坐标求解，再用 `Q_board` 变换回世界。
    共同转向因此同时作用于座舱和整条手臂的位置，且仅作用一次。
  - 右手握持点可以按车身 X/Y/Z 做初始修正。两种模式都不是实测平移；
    当前数据不能可靠自动判断是否离把，必须人工选择。
- 有效相邻样本间隔 ≤250 ms 时使用四元数球面插值，不直接插值欧拉角。
  超过 250 ms 未更新时不再显示有效姿态；未配对或码表姿态缺失时隐藏模型手臂，
  避免用不同步数据推导位置，参考磁北仍然可见。

## 启动

在 `code` 目录执行（Python 3.10+）：

```sh
python3 -m venv tools/imu_web/.venv
tools/imu_web/.venv/bin/python -m pip install -r tools/imu_web/requirements.txt
tools/imu_web/.venv/bin/python tools/imu_web/server.py --port 8766
```

访问 <http://127.0.0.1:8766>，选择设备原始 CSV 或合并 CSV，再点击上传。
Three.js **0.180.0** 和 OrbitControls 已附在 `vendor/`，来自同版本的
[官方 npm 发布包](https://www.npmjs.com/package/three/v/0.180.0)，
保留原始 [MIT 许可证](vendor/LICENSE)。浏览器运行不访问 CDN，不需要 Node/npm。
服务只监听本机，不上传到外部服务。该目录依赖项目内共享分析模块，
并非脱离项目单文件应用。停止服务按 Ctrl+C。

## 逻辑与物理边界

- `cda_postprocess.py` 是气动阻力面积分析，不包含双 IMU 姿态算法，
  不应将 CdA 计算误用于三维设备位置。
- 直接复用 `../imu_to_bvh_hdf5.py` 的 `load_csv` 和
  `estimate_orientations` 的互补倾斜估计（tau=0.5s）。
  h5py 是这个共享模块的导入依赖，本服务本身不写 HDF5。
- 共享验证检查列、uint32 时间回绕、有效标志和配对时间差；
  有效配对最大年龄 250ms、最大 skew 100ms。不合法 CSV 返回可见的 HTTP 错误。
- 加速度模长 <0.05g 的传感器样本显式标为不可用，并统计数量，
  不伪造角度，也不终止整段仍含有效数据的日志。没有可用同步数据时拒绝上传。
- 重新分析时，将陀螺仪向量通过倾斜矩阵投影到水平世界的向上轴，再积分得到相对
  转向估计，而非直接积分各设备原生 Z 轴。这修正了正装/倒装设备共同水平转向时
  因原生 Z 轴方向相反导致的显示反向。不是完整惯导或磁融合算法。
- 姿态为 `Rz(相对水平转向) * Tilt(t) * Tilt(reference).T`，
  以第一个可用配对样本建立参考。每个传感器使用自己的时间戳；
  重复/异常时间不积分，超过 1 秒的间断不积分航向。
- 原始 WT901 欧拉角保留在 JSON；没有磁校准证据时，不将其中 yaw 宣称为磁北。
  导出 `board_heading_change_deg`、`wt_heading_change_deg` 和明确的参考元数据。
- 使用 `Rb.T @ Rw` 计算相对三维转角，不直接相减欧拉角。传感器安装轴仍未完整标定，
  不能把初始对齐与简单重力补偿当作精确安装标定。
- **IMU 日志不能可靠恢复绝对平移、绝对航向或人体关节角。**
  这里呈现相对初始姿态的设备方向变化，不是定位系统。
  简化倾斜/水平转向估计仍有 yaw 漂移，尤其长日志可能出现很大的累积误差；
  手臂复杂转动也不能仅靠水平角速度积分精确还原航向。强动态加速度、长采样间断、
  传感器丢失和安装轴误差会降低结果可信度；并非完整惯导融合。
  缺失的设备不画方向箭头，未配对帧不计算对比角。
- 每次成功上传替换上一次数据。数据只驻留内存，重启清空；
  无数据库、无多用户隔离，不适合直接暴露公网。限制原文件 64 MiB，
  并串行分析。`/api/playback` 提供剔除原始测量列的全量姿态，
  `/api/analysis` 仍保留原始测量列。旧 `/api/frame` Matplotlib 快照端点仍可用，
  因此 Python 依赖保留 matplotlib，但网站播放不使用该端点。
- 时间轴覆盖全部原始行。播放使用原始毫秒时间，不压缩时间间隔；
  暂停拖动可逐行查看。

## 测试

```sh
tools/imu_web/.venv/bin/python -m unittest tools.imu_web.test_server -v
```

验证已知 90° 转动、坐标矩阵、兼容 PNG 端点、时间回绕、
低加速度与丢失样本、非法输入、HTTP 上传/姿态下载/数据替换、本地模块安全路由。
浏览器打开网站后在控制台执行：

```js
await import("/test_scene.js").then(module => module.runTests())
```

使用真实 Three.js 几何体验证尺寸、38 cm 把宽、8 cm 码表前伸、共同转向只叠加一次、
固定水平参考北、可设置的人工航向、支撑握持点约束、离把腕部活动范围和前臂长度、
45° 中点插值、时间轴边界、长间断及无效数据处理。
Python 回归包括主板倒装、手臂正装时共同 90° 水平转向的已知原始输入。
这些测试不证明硬件安装标定或惯性定位精度。
