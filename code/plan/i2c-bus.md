## 1. 问题：同地址的两片 FS3000

| 事实 | 说明 |
| ---- | ---- |
| FS3000 地址固定 | 7-bit `0x28`，**无地址选择脚**，不能通过 ADDR 引脚或改地址区分 |
| 需要两片 | V 形视风探针需要两片 FS3000 相对车头各 ±45° 张开、同点安装，才能解出视风向量 |
| I2C 限制 | 同一总线上**不能有两个 0x28**，否则地址冲突、读回数据不可区分 |

**本质**：不是"传感器不支持"，而是"同址设备需要电气隔离"。分路就是把它们放到**互相独立的电气域**上，
使 MCU 每次访问时**同一时刻只有一个 0x28 在总线上应答**。

> 现有代码其实已经按这个思路写好：`WindProbe::begin(TwoWire &w1, TwoWire &w2, ...)` 接收**两条总线**，
> `_left.begin(w1, 0x28)` / `_right.begin(w2, 0x28)`，`read()` 里先读左再读右。
> **缺的只是硬件上第二条总线的物理接线与初始化**（见 §3）。

## 2. 方案对比：总线分路 vs I2C MUX vs AFS3000

| 方案 | 硬件成本 | 是否需要改传感器 | 占用 IO | 复用性（将来加更多同址设备） | 结论 |
| ---- | -------- | ---------------- | ------- | ---------------------------- | ---- |
| **A. 双总线分路**（MCU 两条 I2C） | **0 元** | 否 | 2 个空闲 GPIO | 差（最多 N 条总线） | ✅ **首选** |
| **B. TCA9548A 8 路 MUX** | **~5~10 元** | 否 | 2 个 GPIO（共用一条总线） | **好**（1 条总线挂 8 路，可多片同址） | 备选/扩展 |
| **C. AFS3000（Renesas 新一代）** | **贵（约 10~20 倍 FS3000，且不好买）** | 需换传感器 | — | — | ❌ **不采用** |
| D. 高速切换（模拟开关 74HC4051 等切 SDA/SCL） | ~2~5 元 | 否 | 3 个 GPIO | 一般 | 不如 B 干净 |

**决策：走 A（零成本），B 作为扩展备选；明确不采购 AFS3000。**

选 A 的理由：

- 板子**已经有**两条可用 I2C：`Wire`（GPIO11/10，12PIN 排针 I2C 口）与 `Wire1`（GPIO15/18，**当前空闲备用脚**）。
- 两片 FS3000 是**固定的 2 片**，不会扩展，双总线足够。
- 无额外元件、无焊接风险，探针线只需"三根线进 A 总线、三根线进 B 总线"。
- 固件侧 `WindProbe` 已支持双总线的接口，改动量最小。

> **为什么不用 AFS3000**：AFS3000 虽支持地址可配/多路，但单价高、供货差、需要重新验证驱动与标定曲线，
> 而要解决的只是"两片同址"这个**单点问题**——用 0 元的双总线就能解决，**用不着升级传感器。
> 预算增量应留给真正带来数据的传感器（GPS、电池采样），而不是为同一功能换来更贵的器件。**

## 3. 推荐方案 A：双总线分路（零成本）

### 3.1 拓扑

```text
                         ESP32-S3
                  ┌───────────────────────┐
   I2C1 (Wire)    │ GPIO11 SDA / GPIO10 SCL│  12PIN 排针 I2C 口
        │         └───────────────────────┘
        │
        ├── FS3000 #L  (0x28)   ← 左臂（探针 −45°）
        └── BME280     (0x76)   ← 可选环境传感器（地址不同，可共享）

   I2C2 (Wire1)   GPIO15 SDA / GPIO18 SCL   （备用脚，第二总线）
        │
        └── FS3000 #R  (0x28)   ← 右臂（探针 +45°）
```

- 两条总线**电压域相同**（3.3V），各自 4.7kΩ 上拉（FS3000 模块一般自带，确认后可不外加）。
- **必须共地**：两片 FS3000 与 MCU 必须共 GND，否则 I2C 采样不可靠。
- **线长与走线**：探针两臂到 MCU 的线尽量等长、远离电机/电机线/功率计线缆，降低 EMI 与总线电容。
- **总线频率**：两片 FS3000 都只需 <400kHz；建议 **I2C2 用 100kHz**（线稍长时更稳），I2C1 保持 400kHz。

### 3.2 与现有代码的对应

现有 `src/wind_probe.{h,cpp}` 已按双总线的接口设计：

```cpp
void WindProbe::begin(TwoWire &w1, TwoWire &w2, float halfAngleDeg) {
  _half = halfAngleDeg * (PI / 180.0f);
  _leftOk  = _left.begin(w1, FS3000_ADDR);     // 左臂 → 总线1
  _rightOk = _right.begin(w2, FS3000_ADDR);    // 右臂 → 总线2
}
```

**需要补齐的三处**（当前 `main.cpp` 是"单 FS3000 + 注释说 Wire1 被触摸占用"的原型状态）：

1. `config.h` 确认 `PIN_I2C2_SDA=15 / PIN_I2C2_SCL=18` 未被其它功能占用（见 §5 冲突项）。
2. `main.cpp` 在 `Wire.begin()` 之后再 `Wire1.begin(PIN_I2C2_SDA, PIN_I2C2_SCL, 100000);`。
3. 把单传感器 `FS3000 windSensor;` 替换为 `WindProbe probe;`，`probe.begin(Wire, Wire1, PROBE_HALF_ANGLE_DEG)`，
   采样时用 `probe.read(windVector)` 拿 `vAlong / vCross / yawDeg / vAir`。

> 注意：`Wire1` 在本板官方 Arduino 示例里曾被用于**触摸屏 CST328**（TP_SDA=GPIO1 / TP_SCL=GPIO3）。
> 本项目触摸走的是自定义总线（`PIN_TOUCH_SDA=1 / SCL=3`），与 `Wire1(GPIO15/18)` 无冲突；
> **实现前需核对 `display_lcd.cpp` 实际用的是哪条 `TwoWire` 实例**，确保 `Wire1` 没有被触摸复用。

### 3.3 采样时序

两片 FS3000 分属不同总线，**可以按顺序读**（一次 `read()` = 读左 + 读右），单次耗时约
2 × (I2C 事务 ~1ms) + 传感器响应时间。`FS3000_SAMPLE_MS / PROBE_SAMPLE_MS = 125ms` 远大于此，
持续采样无压力。即便两条总线在硬件上并行也无需并行读——**顺序读更简单、更可预测**。

## 4. 方案 B：TCA9548A 分路（备选）

若将来出现以下任一情况，可切到 MUX：

- 想**只用一条总线**把所有 I2C 设备串起来（省 GPIO / 简化线束）。
- 要接**第 3 片及以上**同址 FS3000，或多台同型号传感器。
- 探针线束需要走**一根排线**到车头。

### 4.1 拓扑

```text
ESP32-S3 Wire (GPIO11/10) ── TCA9548A (0x70, 地址可配 0x70~0x77)
                                   ├─ CH0 ── FS3000 #L (0x28)
                                   ├─ CH1 ── FS3000 #R (0x28)
                                   ├─ CH2 ── BME280 (0x76)
                                   └─ ...（每通道电气隔离，可重复挂 0x28）
```

### 4.2 用法要点

- 访问前先写 `0x70` 选择通道（`write(1 << ch)`），**切换通道有建立/释放时序**（约几十 µs）。
- 通道切换后**不要紧接**读器件，给一点延时；连续采两片时"选路→读→选路→读"即可。
- MUX 供电 3.3V，自身占用一条总线；**上拉只保留在总线一侧**，通道侧不加，避免重复上拉。
- TCA9548A 是**当前唯一"几块钱解决同址冲突"的标准做法**，比模拟开关干净。

> 成本判断：TCA9548A ≈ 5~10 元，**远低于 AFS3000**，且能覆盖未来所有同址扩展。
> 但当前只有 2 片 FS3000，**方案 A 已足够，B 暂不做**，避免为不存在的问题多焊一块板。

## 5. 当前板卡 I2C 资源盘点与分配表

### 5.1 板载 I2C 设备（Waveshare 官方确认）

| 地址 | 设备 | 说明 |
| ---- | ---- | ---- |
| `0x51` | PCF85063 RTC | 板载 RTC（与 `plan/time-source.md` 相关，**可复用于 FIT 时间戳**） |
| `0x6B` | QMI8658 IMU | 板载六轴（本机未使用） |
| `0x7E` | CST328 触摸 | 板载触摸屏控制器 |

> **重要结论**：板载器件占用了 `0x51 / 0x6B / 0x7E`。`0x28`（FS3000）与 `0x76`（BME280）**不与它们冲突**。
> 另外，官方确认板载有 **Battery Recharge Manager** 与 **Charging 指示灯**——**充电管理已在板上**，
> 但**电量计不在 I2C 上**（否则会出现在占用地址列表里）。电量采样方案见 [`plan/battery-power.md`](./battery-power.md)。

### 5.2 本项目 I2C 引脚分配（建议）

| 总线 | 实例 | 引脚 | 速率 | 挂载设备 | 状态 |
| ---- | ---- | ---- | ---- | -------- | ---- |
| I2C1 | `Wire` | SDA=11, SCL=10 | 400kHz | FS3000 #L (0x28)、BME280 (0x76，可选) | ✅ 在用 |
| I2C2 | `Wire1` | SDA=15, SCL=18 | 100~400kHz | FS3000 #R (0x28) | ⚠️ **规划启用**（当前空闲） |
| 触摸 | `Wire`(自定义) | SDA=1, SCL=3 | 400kHz | CST328 (0x7E) | ✅ 在用（独立于上面两条） |
| 预留 | `Wire1`(复用) | — | — | （可选）TCA9548A 0x70、或 PCF8563（地址 0x51 需避开板载 RTC） | 见 §5.3 |

### 5.3 ⚠️ 引脚冲突：GPIO15 同时被 GPS PPS 与 I2C2 SDA 占用

`config.h` 现状存在一处**矛盾**：

```c
#define PIN_I2C2_SDA  15      // I2C2（备用脚）
#define PIN_GPS_PPS   15      // "仅 GPS_USE_PPS=1 时生效"
```

虽然 `GPS_USE_PPS = 0`（默认不启用），不会造成运行故障，但两处都写了 15，**一旦开启 PPS 就会冲突**。
本规划建议：

- **I2C2 SDA 保留 GPIO15 / SCL 保留 GPIO18**（这两脚就是 12PIN 排针上的备用脚，天然适合接传感器）。
- **PPS 换到别的空闲脚**（例如 GPIO13 已被 QMI_INT 占用、GPIO12 已被 QMI_INT2 占用——**需核对剩余可用 IO**，
  可从 GPIO 1/2/3/4 之外选择，或干脆**本代不使用 PPS**）。
- 在 `config.h` 注释里**显式写明"GPIO15 已归 I2C2，PPS 另选"**，避免后人再踩坑。

> 这不是本模块的"必须解决"项，但属于**规划层面的技术债**，应在实现双总线时顺手清理注释/宏定义。

## 6. 固件实现要点

### 6.1 建议抽象

把"总线归属"从 `WindProbe` 内部收拢成一张配置表，避免硬编码：

```cpp
// wind_probe.h 片段（示意）
struct ProbeBusConfig {
  TwoWire *busLeft;    // &Wire
  TwoWire *busRight;   // &Wire1
  uint8_t  addrLeft;   // 0x28
  uint8_t  addrRight;  // 0x28
  uint32_t clockHz1;   // 400000
  uint32_t clockHz2;   // 100000（线更长时可降速）
};
```

### 6.2 健康与降级

- 两臂**分别**报告 `leftOk() / rightOk()`（现有接口已有），任一臂故障时 `read()` 返回 false。
- **单臂降级**：若只有一臂在线，可退化到"单传感器模式"（只能给 vAir 的轴向分量，侧风失效），
  在 UI/日志里标注 `windValid=0` 或 `probeDegraded=1`，避免误把坏数据当有效风速。
- 恢复：沿用现有 `main.cpp` 里 `windSensor.present()` 的周期性重探测（`lastWindProbeMs`），
  对**两条总线各自**做"未发现 → 5s 后重试 `begin()`"。

### 6.3 采样与日志字段

- `WindProbe::read()` 输出 `vAlong / vCross / yawDeg / vAir`；
- 与 [`plan/README.md`](./README.md) §2.5 呼应，建议 CSV 新增 `vCrossMps` 与 `windValid` 列；
- 若两臂读数差异过大（例如 `|v1−v2|` 超出合理范围），置 `windValid=0` 并计数，便于事后诊断探头安装偏差/污染。

### 6.4 与其它模块的共享

| 模块 | 与 I2C 分路的关系 |
| ---- | ----------------- |
| BME280 | 地址 0x76 与 FS3000 0x28 不冲突，可留在 I2C1 与 #L 共享 |
| 板载 PCF85063 RTC | 在**板载 I2C**（GPIO10/11），本项目 `Wire` 也走 GPIO10/11——**需确认是否会与板上 RTC/IMU 抢总线**（官方 I2C 口与板载器件同总线）。若冲突，把外部 FS3000 挪到 I2C2，避免每次初始化干扰板载器件 |
| 电池采样 | 若用 I2C 电量计（MAX17048/BQ27441 等），本代**不建议**（见 battery-power.md §3），优先 ADC 分压 |

## 7. 落地 Checklist

### 硬件

- [ ] 探针左臂 FS3000 接 I2C1（SDA=11 / SCL=10），右臂接 I2C2（SDA=15 / SCL=18）
- [ ] 两臂**共地**；确认两片 FS3000 模块自带或外加 4.7kΩ 上拉（不要重复上拉）
- [ ] 探针线束等长、远离电机/大电流线缆；必要时 I2C2 降到 100kHz
- [ ] 核对 GPIO13/GPIO12（QMI INT）等已被占用的脚，为 PPS 另选或本代不用 PPS

### 固件

- [ ] `main.cpp` 增加 `Wire1.begin(PIN_I2C2_SDA, PIN_I2C2_SCL, 100000)`
- [ ] 用 `WindProbe` 替换单 `FS3000 windSensor`，`begin(Wire, Wire1, PROBE_HALF_ANGLE_DEG)`
- [ ] 两臂独立健康检查 + 单臂降级 + 双总线各自重探测
- [ ] CSV/FIT 新增 `vCrossMps` / `windValid`
- [ ] `config.h` 清理 `PIN_GPS_PPS` 与 `PIN_I2C2_SDA` 的 GPIO15 冲突注释

### 验证

- [ ] `pio run -e esp32s3` 编译通过；`sh test/host/run.sh` 通过（含 FS3000 解析/校验和用例）
- [ ] 真机：I2C 扫描确认两总线各只有 1 个 0x28；拔掉一臂时另一臂读数不受影响
- [ ] 标定对比：静止/风扇直吹下，两臂读数一致性与 ±45° 解算结果合理
- [ ] 长时运行：两臂 125ms 周期采样数小时无丢帧、无总线锁死
