# 一个小小的"气动测试器"：我们是怎么把它做出来的

> 这是一篇写给同学看的项目故事。不讲复杂的公式和代码，
> 只讲清楚四件事：**我们为什么想做它、用了哪些零件、路上踩了什么坑、怎么想办法爬出来的。**

---

## 一、这个项目从哪来？

喜欢骑车的朋友大概都有过这种体验：你趴得越低、越"像一条咸鱼贴"在车上，
好像就越省力。可到底省了多少？凭感觉说不清。

在专业自行车比赛里，有个词叫 **"气动"（空气动力学）**。运动员和工程师会用风洞、
用很贵的设备来测：我这个姿势，风阻到底多大？换一个姿势，快了多少？

风洞太贵，专业设备也贵。我们就想：**能不能用一块几十块钱的单片机，做一个"迷你版"的测试装置？**

它的目标很朴素：

- 骑车的时候，测一下迎面吹来的**风速**；
- 同时读到功率计上的**踩踏功率**；
- 把这些数据记下来，回头分析：同样的功率下，**换姿势是不是更快**。

我们不是在造一个能上奥运会的精密仪器，而是在做一个**能上手、能对比、能看懂**的
小原型。这就是整个项目的起点。

---

## 二、我们选了哪些"零件"？

做这个东西，就像搭一套乐高。我们一块一块挑：

| 零件 | 它是什么 | 为什么选它 |
|---|---|---|
| **ESP32-S3 触摸屏开发板** | 一块带彩色小屏幕、能触摸、还能连蓝牙和 Wi-Fi 的"大脑" | 一块板子就把"计算 + 显示 + 无线"全包了，省事又便宜 |
| **FS3000 风速传感器** | 一个指甲盖大小、能测风速的小芯片 | 便宜、用两根线就能读数据。**原型阶段先只买一片**，控制成本 |
| **功率计 / 骑行台** | 骑车时测"踩多大力"的设备 | 骑车的人往往已经有了。它有两种"说话方式"：蓝牙（BLE）和 ANT+，我们都支持 |
| **BME280（可选）** | 测温度、气压的小传感器 | 空气冷热、气压高低会影响空气密度，算阻力时要用 |
| **姿态传感器（可选）** | 绑在胸口的小盒子，能感知身体倾斜角度 | 用来记录"你趴得有多低" |
| **TF 存储卡** | 一张小内存卡 | 把数据存成表格，骑车回来插电脑就能分析 |

**一个很关键的选择：先只买一个风速传感器。**

专业方案要两个传感器摆成"V 字形"，才能算出风是从斜前方多少度吹来的。
但那要多花一倍的钱，还要更复杂的机械结构。我们想：**先用一个把整个流程跑通**，
证明"测风 + 记功率 + 比姿势"这件事能成，再考虑升级。这叫**先做原型，再谈升级**。

---

## 三、路上踩过的"坑"，以及我们怎么想的

真正做硬件，**代码写对只是开始，能稳定跑起来才是难关**。下面几个坑，是我们真金白银踩出来的。

### 坑 1：界面突然"卡住"了，但机器其实没死

**现象**：在屏幕上切来切去，切着切着，画面就不动了。像死机一样。

**我们一开始以为**：完蛋，程序崩了。

**后来怎么发现的**：我们把开发板接到电脑上，让它"边说边做"——每秒钟打印一行
"我还活着"的信息（里面有个不断变大的数字，叫时间戳）。

结果发现：**画面虽然不动了，但那些"我还活着"的信息还在一条一条往外蹦！**
那个数字一直在变大。

**这说明什么？** 机器的"心脏"——主循环——**根本没停**，
只是**"脸"（屏幕刷新）不动了**。就像一个人心脏还在跳、还能走路，
但眼睛闭着不睁开了。问题出在"显示"这一块，不是整台机器死了。

**真正的病根**：屏幕上的界面是由一个叫 **LVGL** 的"画图程序"负责的。
它干活需要一块**自己的"草稿纸"（内存）**。我们查了它的默认设置——
它只肯给自己 **48KB** 的草稿纸（大约相当于一张很小的便签）。

可我们的界面有十几个页面，每个页面都有很多按钮、文字，
还有中文那种笔画特别多的大字。**要画的东西太多，48KB 的草稿纸不够用了**，
一画就"墨水用光"，然后它就不画了——于是画面冻结。

**怎么解决的**：把它的"草稿纸"加大到 **128KB**。
内存够用了，画得开了，卡屏问题就好多了。

> 给朋友的启发：**"卡住"不一定是死机。先分清"谁停了"——心脏停了，还是眼睛闭上了？**
> 这是排查问题最省时间的一步。

### 坑 2：插上存储卡，机器开不了机

**现象**：不插 TF 卡，一切正常；一插卡，开机就卡住，屏幕停在半路。

**怎么定位的**：把卡拔掉再开机——嘿，正常了！那问题肯定跟卡有关。
再看电脑上的"启动日志"，发现它卡在"**挂载存储卡**"这一步。

**为什么会卡**：读取存储卡需要"握手"——机器问卡"你在吗？",
卡要回答。如果卡没插好、接触不良，机器就会**一直问、一直等**，
把整个开机流程堵死在这里。它本来应该"问几次没人理就放弃"，
但默认行为是"死等"。

**怎么解决的**：
1. **给等待设一个上限**——问几次没回应就算了，先把机器开起来，卡的事以后再说；
2. **每次往卡里写东西之前，先确认"卡还在不在"**——不在就别写，
   免得对着一张"已经拔走的卡"猛写，报一堆错。
3. 提醒用户：存储卡要用 **FAT32** 格式，太新的大卡（比如 64G、exFAT 格式）它不认。

> 给朋友的启发：**外部设备可能"不听话"。程序要假设"它可能不在"，而不是"它一定在"，**
> 这样才不会因为一个小零件把整台机器拖死。

### 坑 3：一开中文界面就卡

**现象**：界面切成中文，某些页面就卡死。

**我们怎么想的**：中文的字笔画多，字体文件大，画起来更"费草稿纸"。
所以它和坑 1 其实是**同一个病根**——内存不够。

**临时对策**：先把中文**关掉**，强制用英文，保证设备能正常用。
等内存问题彻底解决后，再单独把中文拿出来慢慢调。

> 给朋友的启发：**遇到"改不动"的地方，先让它"能用"，再回头"做好"。**
> 先保证车能骑，再研究怎么骑得更快。

### 坑 4：烧录（把程序装进板子）老是失败

**现象**：往板子里装程序，装到一半就报错断开。

**两个原因**：
1. 装得太快——就像往杯子里倒水倒太猛，会洒出来。**把速度降下来**就稳了；
2. **有别的程序正"占着"这根数据线**。就像两个人抢一部电话，谁都说不清。
   我们发现有个后台程序还开着串口监视器，**把它关掉**，就通了。

**怎么解决的**：
- 降低装程序的速度；
- 装之前**先关掉所有占着数据线的程序**；
- 文件比较大的话，**切成一小块一小块地装**，每块装完检查一下"对不对"，稳得多。

> 给朋友的启发：**"装不进去"很多时候不是代码的错，而是"路"被占了、或者"车速"太快。**

## 四、我们解决问题的"通用套路"

回头看，我们其实反复用了几招，你可以记住它们，以后做别的小项目也用得上：

1. **先分清"谁停了"**：心脏（主循环）停了，还是眼睛（显示）闭上了？
   —— 看那个每秒变大的"时间戳"就知道。
2. **用排除法缩小范围**：拔掉卡就正常 → 问题在卡；关掉后台程序就通 → 问题在占线。
3. **从最简单的地方找证据**：让程序"边做边喊话"（打印日志），
   卡在哪一步，日志就停在哪一行前面。
4. **先能用，再做好**：中文先关掉、卡先不写，保证基本功能活着，再逐个攻克。
5. **别只盯着代码**：内存够不够、线插没插好、有没有别的程序抢资源——
   这些"代码之外"的事，往往是真凶。

## 五、这个项目最后做成了什么样？

- 一块能触摸的小彩屏，实时显示**风速、功率、踏频**；
- 可以用**蓝牙**或 **ANT+** 连接市面上的功率计，甚至能自己"造"一个虚拟功率计来练手；
- 数据每秒记一行，存进 TF 卡的表格里，插电脑就能用脚本分析；
- 还有一个**不用硬件**的网页模拟器，朋友们在电脑上就能先玩一遍界面。

**它想回答的问题只有一个**：*同样的力气，换个姿势，风阻变了多少？*

精度它不是最顶尖的，自然风一乱，数字就会飘。所以我们一直强调：
**看"同一条件下，两种姿势谁更好"，而不是死抠某个绝对数字。**

---

## 六、给想做类似项目的朋友几句话

- **别怕"卡住"**。卡住不是失败，是项目在告诉你"这里有东西没搞明白"。
- **先做小的**。一个传感器、一个页面、能跑通，就已经赢一大半了。
- **多打日志**。程序不会说话，但你可以让它"边做边喊话"。
- **分清主次**。先让东西能用，再让它变好。

这个项目没有多高深的技术，它靠的就是**一次次"卡住 → 观察 → 猜想 → 验证"**。
你手里的任何一个小装置，只要愿意这样一点点抠，都能做出点东西来。
