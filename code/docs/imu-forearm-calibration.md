# 双 IMU 前臂佩戴与功能性标定

## 目的与边界

WT9011DCL-BT50 使用官方腕带固定在右前臂远端：Type-C 朝手肘，
LOGO、按钮面与手背同侧。不得以水平画三个圈代替三维安装标定：
平移圆轨迹不能唯一确定传感器轴向，单一旋转激励也不足，
向心加速度还会污染重力估计。静止的码表和运动的腕带不是共同刚体，
不能直接用两者角速度相关性求安装旋转或蓝牙延迟。

本功能估计的是功能性前臂参考与主板安装参考，不是人体关节定位、
磁北标定或制造商原生 XYZ 认证。它改善轴向、符号与初始姿态匹配，
不保证绝对平移、长期无漂移航向或时间同步精度。

## 引导流程

只可停车操作，扶稳自行车、前轮摆正。标定与记录不能同时开始。

实体屏幕的 IMU 设置使用固定五页，不需要滑动滚屏。进入设置先显示
**连接 / 搜索设备**、连接状态和收藏按钮；底部固定“上一页 / 下一页”
与页码。之后依次为佩戴示意、轴向选择与开始、标定动作与结果、
原有直立/前倾姿态分类设置。首尾按钮自动禁用，翻页保留轴向和佩戴勾选；
新连接的数据就绪提示会清除勾选，重新从连接页进入。

翻页仅切换说明，不推进标定状态。必须在轴向页核对佩戴并点击开始，
随后真实传感器数据驱动动作阶段；阶段变化自动显示标定进度页，
普通数据刷新不会打断手动翻页。原有姿态分类设置与前臂轴向标定仍相互独立。

1. 蓝牙订阅成功后等待两颗 IMU 的新鲜、完整加速度和角速度数据；
   旧版只有角度的通知不能进入标定。链路连接不等于数据就绪。
   WT 输出有效数据需至少 20 Hz；不足时通过厂商应用设置输出速率后重试。
   固件不发送未经验证的厂商配置寄存器写命令。
2. 屏幕显示佩戴提示与手臂/接口示意，用户确认腕带方向及固定情况。
   同时选择**主板原生哪个有符号轴指向车头**，不能仅凭重力猜测前方；
   若不知道，须先对照板载安装轴图确认。默认选项不代表自动识别。
3. 右前臂水平、手指向车头、手心向下，静止约 3 秒。
   LOGO 面应朝上。使用独立样本估计重力与两颗陀螺仪偏置。
4. 前臂仍指向车头，先向拇指朝上的方向缓慢翻掌，再回到手心向下，
   连做两次。不能只弯手腕。按首个有符号转动估计前臂长轴，
   要求足够角度、往返与重力参考一致。
5. 回到水平后，抬起前臂约 30–45 度再放回，做两次。
   验证第二个非平行转轴及方向，不把所有动作强制拟合为成功。
6. 正常握住右手变头，静止约 3 秒。显示质量结果，由用户明确
   确认握持点和佩戴未滑动后应用；软件只能检查稳定与粗略倾角，
   不能自动证明手掌接触手变头或恢复上臂长度。

任一阶段数据中断、码表明显移动、动作方向/轴不符或超时，显示原因并重试。
允许取消，未标定时仍可记录原始数据，但必须明确标记无有效标定。
重新连接、数据丢失、设备换代、佩戴改变后需要重新标定/确认。
本版本不跨重启复用腕带标定，避免重新佩戴后静默套用。

## 坐标与实现约定

参考系右手制：X 车头/前臂伸出方向、Y 左、Z 上。
静止重力确定上方向，用户选择的主板车头轴经水平投影确定主板参考 X；
翻掌第一段角速度确定前臂参考 X 的符号。通过叉积正交化得到
两个 determinant +1 的固定矩阵：

`a_ref = R_native_to_reference * a_native`

`gyro_ref = R_native_to_reference * (gyro_native - stationary_bias)`

这两个固定矩阵把**标定时刻**的原生轴换到约定的参考方向。
动作之后的 `*_ref_*` 向量不是实时世界坐标，需要后处理积分姿态；
不能把固定轴变换误称为完成了动态车体补偿或前臂四元数融合。
前臂参考来自规定手势，错误手势仍可能满足数值检查，必须人工确认。

整车双轮贴地是 Three.js 的地面约束，不通过修改主板原始俯仰/侧倾实现，
也不是判断传感器标定正确的依据。本次不改变已有姿态分类器的直立/前倾标定。

## 记录契约

- 保留现有原生列、时间戳、序列号和 paired 语义。
- 新增每行 `calibration_id`、`calibration_valid` 及两颗 IMU 的
  `*_ref_ax_g` / `*_ref_gx_dps` 等 12 个参考向量列。
- 无标定、断流、未配对时参考列为 NaN，原始列仍按原有规则保存。
- 每个 IMU CSV 同名 `.json` 写入算法版本、标定 ID、设备地址、
  有效区间起点、矩阵、偏置、动作质量、用户确认与会话 UTC 锚点。
  元数据写入/同步失败则该 IMU 日志明确失败，不生成看似已标定的记录。
- 一次日志的标定快照不可变；录制中断流导致后续行失效，不能自动恢复
  旧校准。再次标定只在停止记录后进行，后续新日志使用新 ID。
- 标定片段以独立 CSV 保留（至少原始向量、采样时间及状态），与正常
  10 Hz IMU 记录分开，按有效新样本采集，目标不低于 20 Hz；
  实际速率/样本数须由报告确认，通知不足时拒绝动作阶段。
- 不覆盖骑行 CSV/FIT，也不修改功率、风速或现有 FIT 字段。
  IMU UTC 锚点表示主机时间对应关系，不消除 BLE 传输延迟。

阶段编号：0 未连接、1 等待原始数据、2 佩戴确认、3 静止参考、4 翻掌、
5 抬臂、6 握把验证、7 待应用、8 已应用、9 失败/取消。
`*_ref_*` 是新增的显式派生列，现有离线工具仍默认读取原始列；
不能假定旧版 BVH/网页已自动识别新标定，分析时应连同同名 JSON 保存。

## 验证

在 `imu_mount_calibration` 原生测试中验证已知旋转、方向错误、重复/陈旧数据、
数据中断、采样率、超时、时间回绕；在 `imu_comparison` 中验证记录前后标定
快照、原始值保留、同名 JSON、CSV 新旧格式兼容及 SD 写入失败。
在真实 LVGL 原生测试中验证中英文字体、首屏连接回调、五页上一页/下一页、
首尾边界、翻页与切换语言后保留选择、忙碌禁用及失败原因显示。
逐页检查无滚动容器、所有可见控件/文字在 240×320 内且无实际滚动偏移。
编译 `pio run -e esp32s3`。模拟不证明实际腕带滑动、RF 时延或人体操作精度；
需要在设备上完成至少一次正向标定与反向动作失败验收，不自动烧录。
