# AFS3000 风速模块兼容改造方案（基于官方数据手册）
> **状态：仅方案设计，未修改任何项目源码**
> 项目：`esp32-fs3000-project`
> 依据：`docs/AFS3系列风..09.pdf`（奥松电子官方说明书，2026年8月版）
> 目标：同一套固件同时支持 **Renesas FS3000** 与 **奥松 AFS3000**
> 日期：2026-10-28
---
## 一、结论先行
**方案可行，改动很小，但有一个硬件前提必须先解决。**
好消息：AFS3000 的协议**比预想的简单**——它和 FS3000 一样是"直接读"，不需要写命令。
坏消息：它**要 5V 供电**，而 FS3000 是 3.3V，**接错会烧模块**。

## 二、两种传感器硬核对比（依据官方手册）
| 项目 | Renesas FS3000-1015 | 奥松 AFS3000 | 差异影响 |
|---|---|---|---|
| **I2C 地址** | 0x28 | **0x28** | 🔴 **完全相同，不能同总线共存** |
| **供电电压** | 3.3V（VDD≤3.6V） | **5V（4.8~5.25V）** | 🔴 **接错烧模块** |
| **读取方式** | 直接读 5 字节 | **直接读 3 字节** | 🟢 都是"读"，流程相似 |
| **返回字节** | `[校验和][高][低][校验][校验]` | `[高8位][低8位][CRC8]` | 🟡 格式不同 |
| **数据位宽** | 12 位（高字节低4位有效） | **16 位**（完整两字节） | 🟡 解析方式不同 |
| **校验算法** | 5 字节之和低8位=0 | **CRC-8，初值0x00，多项式0x31** | 🟡 算法不同 |
| **换算公式** | 查表插值（13点曲线） | **风速 = 点数 × 0.005** | 🟢 **AFS3000 更简单** |
| **量程** | 0~15 m/s | 0~15 m/s（点数 0~3000） | 🟢 量程一致 |
| **响应时间** | 125 ms | **1000 ms（1秒）** | 🔴 **采样周期必须改** |
| **精度** | — | 5%~10% F.S | — |
| **工作温度** | — | 0~50℃ | — |
| **通信速率** | 400 kHz | 10~400 kHz | 🟢 兼容 |
### 关键结论
1. **地址冲突是硬约束**：两者都是 0x28，**物理上不能同时接在同一条 I2C 总线上**。所以只能"二选一"，这直接排除了"自动探测"方案。
2. **供电必须分开处理**：AFS3000 需要 5V。项目板上有 VBus（5V）引脚，但 README 明确警告"VBus 是 5V，严禁给 FS3000 供电"。所以接线必须区分。
3. **采样周期必须可配**：FS3000 是 125ms，AFS3000 是 1000ms。用 125ms 读 AFS3000 会读到大量重复值，浪费总线且无意义。

## 三、AFS3000 通信协议（手册原文提取）
### 3.1 读取流程（极简）
```
主机: [START] [0x28<<1 | READ] [读 3 字节] [STOP]
从机返回:
  Byte 1: 传感器点数高 8 位
  Byte 2: 传感器点数低 8 位
  Byte 3: CRC8
```
**注意：不需要写任何命令字！** 这和 FS3000 完全一样，都是直接读。
> 手册 5.1 节原文："在风速传感器连接到客户主机后，会以 10ms 为周期进行数据采集。在一次测量周期结束时，数据输出寄存器将被刷新。"
### 3.2 CRC-8 算法（手册 5.2.3 节原文代码）
```c
u8 Calc_CRC8(u8 *data, u8 Num)
{
    u8 bit, byte, crc = 0x00;
    for (byte = 0; byte < Num; byte++) {
        crc ^= (data[byte]);
        for (bit = 8; bit > 0; --bit) {
            if (crc & 0x80)
                crc = (crc << 1) ^ 0x31;
            else
                crc = (crc << 1);
        }
    }
    return crc;
}
```
- 初值：**0x00**
- 多项式：**0x31**（注意：不是例程里的 0x131！手册明确写 0x31）
- 校验范围：前 **2 字节**（点数高8位 + 点数低8位）
- 对比第 3 字节
> ⚠️ **重要修正**：老大给的 STM32 例程里写的是 `POLYNOMIAL 0x131`，但**官方手册明确是 0x31**。0x131 是 9 位（含最高位），实际运算时 `(crc<<1)^0x131` 在 u8 类型下等价于 `^0x31`（高位被截断）。所以两者**结果相同**，但按手册写 0x31 更清晰。
### 3.3 风速换算公式（手册 5.2.4 节原文）
```
风速[m/s] = 点数值 × 转换系数
转换系数 = 0.005
示例：点数 2000 → 2000 × 0.005 = 10 m/s
```
**这比 FS3000 的查表插值简单得多**——一个乘法搞定。
### 3.4 读传感器 ID（可选，用于型号验证）
```
主机发送: [0x31] [0xAE]
从机返回: [ID高16位(2字节)] [CRC8] [ID低16位(2字节)] [CRC8]
```
可用于上电时验证接的是不是 AFS3000。

## 四、方案设计
### 4.1 方案选型
| 方案 | 可行性 | 说明 |
|---|---|---|
| **A. 编译期宏切换** | ✅ **推荐** | 地址冲突决定了只能二选一，编译期切换最干净 |
| B. 运行时自动探测 | ❌ **不可行** | 两者地址都是 0x28，I2C 无法区分 |
| C. 运行时手动选择 | ⚠️ 可行但复杂 | 需改 UI（2422行），有 LVGL 卡屏风险 |
**采用方案 A**：`config.h` 一个宏切换，改动最小、零运行时开销、不影响现有 FS3000。
### 4.2 核心设计：统一接口别名
项目架构天然支持——`main.cpp` 只调用 `windSensor.readMps(float&)` 一个方法。
```c
// fs3000.h 顶部加条件编译
#pragma once
#include "config.h"
#if WIND_SENSOR_TYPE == WIND_SENSOR_AFS3000
  #include "afs3000.h"
  using WindSensor = AFS3000;
#else
  // FS3000 类定义保持原样，一行不动
  class FS3000 { ... };
  using WindSensor = FS3000;
#endif
```
`main.cpp` 只需改一行：
```c
FS3000 windSensor;   →   WindSensor windSensor;
```

```c
// ============================================================================
// 风速传感器型号选择
//   FS3000  : Renesas，3.3V 供电，I2C 0x28，读 5 字节，125ms 响应
//   AFS3000 : 奥松电子，5V 供电，I2C 0x28，读 3 字节，1000ms 响应
//   ⚠️ 两者地址相同，物理上不能同时接在同一条 I2C 总线
//   ⚠️ 供电电压不同，接线前务必确认，接错会烧模块
// ============================================================================
#define WIND_SENSOR_FS3000   0
#define WIND_SENSOR_AFS3000  1
#define WIND_SENSOR_TYPE     WIND_SENSOR_FS3000   // ← 改这里切换
// ============================================================================
// AFS3000 参数（依据奥松官方说明书 2026-08 版）
// ============================================================================
#define AFS3000_ADDR            0x28     // I2C 地址（与 FS3000 相同）
#define AFS3000_RESPONSE_BYTES  3        // 返回字节数：高8位 + 低8位 + CRC8
#define AFS3000_SAMPLE_MS       1000     // 采样周期（手册响应时间 1 秒）
#define AFS3000_SCALE           0.005f   // 转换系数：风速 = 点数 × 0.005
#define AFS3000_MAX_COUNT       3000     // 最大点数（对应 15 m/s）
#define AFS3000_MAX_MPS         15.0f    // 量程上限
#define AFS3000_CRC_POLY        0x31     // CRC8 多项式
#define AFS3000_CMD_ID_HIGH     0x31AE   // 读 ID 高 16 位（可选）
#define AFS3000_CMD_ID_LOW      0x31AF   // 读 ID 低 16 位（可选）
// 采样周期按传感器自动适配
#if WIND_SENSOR_TYPE == WIND_SENSOR_AFS3000
  #define WIND_SAMPLE_MS  AFS3000_SAMPLE_MS
#else
  #define WIND_SAMPLE_MS  FS3000_SAMPLE_MS
#endif
```
### 4.5 AFS3000 驱动实现要点
```c
// afs3000.cpp 核心逻辑（示意）
bool AFS3000::readMps(float &mps) {
  ++_readAttempts;
  if (!_present) { _lastError = ReadError::NotPresent; return false; }
  // 1. 直接读 3 字节（无需写命令）
  memset(_lastFrame, 0, sizeof(_lastFrame));
  const uint8_t received = _w->requestFrom(_addr, (uint8_t)3);
  _lastBytesReceived = 0;
  while (_w->available() > 0) {
    const int v = _w->read();
    if (v < 0) break;
    if (_lastBytesReceived < 3) _lastFrame[_lastBytesReceived++] = (uint8_t)v;
  }
  if (received != 3 || _lastBytesReceived != 3) {
    ++_shortReads;
    if (++_consecutiveFailures >= 8) _present = false;
    _lastError = ReadError::ShortRead;
    return false;
  }
  // 2. CRC8 校验（初值0x00，多项式0x31，覆盖前2字节）
  const uint8_t crc = crc8(_lastFrame, 2);
  if (crc != _lastFrame[2]) {
    ++_checksumErrors;
    if (++_consecutiveFailures >= 8) _present = false;
    _lastError = ReadError::Checksum;
    return false;
  }
  // 3. 解析 16 位点数
  _raw = ((uint16_t)_lastFrame[0] << 8) | _lastFrame[1];
  // 4. 换算：风速 = 点数 × 0.005，钳位到 [0, 15]
  float v = (float)_raw * AFS3000_SCALE;
  if (v < 0) v = 0;
  if (v > AFS3000_MAX_MPS) v = AFS3000_MAX_MPS;
  mps = v;
  ++_readSuccesses;
  _consecutiveFailures = 0;
  _lastError = ReadError::None;
  return true;
}
// CRC8（手册原文算法）
uint8_t AFS3000::crc8(const uint8_t *data, size_t len) {
  uint8_t crc = 0x00;
  for (size_t i = 0; i < len; i++) {
    crc ^= data[i];
    for (uint8_t bit = 8; bit > 0; --bit) {
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ AFS3000_CRC_POLY)
                         : (uint8_t)(crc << 1);
    }
  }
  return crc;
}
```
**公开接口与 FS3000 完全一致**：`begin()`、`readMps()`、`lastRaw()`、`present()`、
`readAttempts()`、`readSuccesses()`、`shortReads()`、`checksumErrors()`、
`lastBytesReceived()`、`lastFrame()`、`lastError()`、`lastErrorName()`。
所以 `main.cpp` 里所有 `windSensor.xxx()` 调用**一行都不用改**。

## 五、硬件接线差异（**最容易出事的环节**）
| 项目 | FS3000 接线 | AFS3000 接线 |
|---|---|---|
| VCC | **3V3**（严禁 5V） | **5V（VBus）** ⚠️ |
| GND | GND | GND |
| SDA | GPIO11 | GPIO11 |
| SCL | GPIO10 | GPIO10 |
| 上拉电阻 | 模块内置 | **需外接 10K 到 3.3V**（手册图7推荐） |
### ⚠️ 三条红线
1. **绝对不能把 AFS3000 接 3V3**——手册要求 4.8~5.25V，3.3V 可能不工作。
2. **绝对不能把 FS3000 接 5V**——FS3000 VDD≤3.6V，接 5V 直接烧毁。
3. **AFS3000 的 SDA/SCL 高电平是 3.3V~VDD**，ESP32 是 3.3V 逻辑，**电平兼容**，无需转换。
### 建议做法
在接线端子上贴标签或用不同颜色的杜邦线：
- FS3000 用 **红线接 3V3**
- AFS3000 用 **黄线接 VBus(5V)**

## 五之二、AFS3000 的 5V 供电怎么接（重点章节）
> 老大问的核心问题：**主板上哪里能给 AFS3000 供 5V？**
> 答案：**12 针排针上有一个 VBus 引脚，就是 5V**。但能不能用、怎么用，取决于您的使用场景。
### 5.2.1 先认清板子上的电源分布
根据 `README.md` 和 `docs/hardware-installation.md` 的实物核对记录，主板 12 针排针丝印完整为：
```
IO15  IO18  RXD  TXD  SDA  SCL  3V3  GND  VBus  D+  D-  GND
                                      ↑     ↑
                                   3.3V   5V（就是它）
```
| 引脚 | 电压 | 来源 | 能带多大负载 |
|---|---|---|---|
| **3V3** | 3.3V | 板载 LDO | 小电流（FS3000 用这个） |
| **VBus** | **5V** | **USB 供电直通** | 取决于 USB 电源能力 |
| GND | 0V | 公共地 | — |
**关键点**：`VBus` 这个名字本身就说明了它的来源——**VBUS 是 USB 总线的 5V 电源线**。
所以它**只有在插着 USB（电脑/充电器/移动电源）时才有 5V**。
### 5.2.2 三种场景，三套方案
#### 场景 A：桌面调试 / 台架测试（**最简单，推荐先用这个**）
**做法**：直接用 Type-C 线接电脑或 5V 充电器，从 12 针排针的 **VBus** 取 5V。
```
AFS3000 引脚       主板 12 针排针
   VCC    ────────→  VBus（5V）
   GND    ────────→  GND
   SDA    ────────→  SDA（GPIO11）
   SCL    ────────→  SCL（GPIO10）
```
| 优点 | 注意 |
|---|---|
| 零成本，不用加任何器件 | ⚠️ **必须插着 USB 才有 5V**，拔线就断电 |
| 5V 直接来自 USB，稳定 | ⚠️ 排针间距 1.27mm，需转接线 |
| 适合验证协议、标定 | ⚠️ 电脑 USB 口一般能提供 500mA，AFS3000 只要 40mA，够用 |
**这是验证 AFS3000 能不能工作的最快路径**，建议老大先这么试。
---
#### 场景 B：电池骑行使用（**真正装车时用这个**）
**问题**：骑行时不插 USB，**VBus 上没有 5V**，AFS3000 就没电了。
**解决方案：3.7V 锂电池 + 5V 升压模块**
```
┌──────────┐    ┌─────────────┐    ┌──────────────┐
│ 18650    │───→│ MT3608 升压 │───→│ 主板 VBus    │
│ 3.7V     │    │ 3.7V→5V     │    │ (5V 输入)    │
└──────────┘    └──────┬──────┘    └──────┬───────┘
                       │                   │
                       └──────────────────→│ AFS3000 VCC
                                           │
                                      GND ─┴─ 共地
```
**推荐器件**（淘宝几块钱）：
| 器件 | 型号 | 说明 |
|---|---|---|
| 升压模块 | **MT3608** | 输入 2~24V，输出最高 28V，最大 2A，可调。调到 5.0V |
| 或 | **XL6009** | 输入 3.6~32V，输出最高 32V，4A，效率更高 |
| 或 | **LM2596 升压版** | 更常见，但效率略低 |
| 电池 | 18650 × 1~2 | 项目文档已推荐 |
| 保护板 | 18650 自带或外接 | 防过放 |
**接线要点**：
1. 升压模块**输入端**接电池（3.7V）
2. 升压模块**输出端**调到 **5.0V**（用万用表量准，别超过 5.25V）
3. 输出接到主板的 **VBus** 引脚（给主板供电）
4. **同时**从同一个 5V 输出点引一路给 AFS3000 的 VCC
5. **所有 GND 必须共地**（电池、升压模块、主板、AFS3000）
> 💡 **重要提醒**：项目文档 `hardware-installation.md` 第 140 行原文就写了：
> 「供电：建议 3.7V 锂电池 + 5V 升压模块（主板 5V 排针），或移动电源。」
> 说明**这个方案本来就是项目设计的既定路线**，不是新发明。
---
#### 场景 C：移动电源供电（**最省事，适合外出测试**）
**做法**：用充电宝 + Type-C 线给主板供电，VBus 自然就有 5V。
| 优点 | 缺点 |
|---|---|
| 零改造，插上就用 | 充电宝体积大 |
| 容量大，能撑一整天 | 需要放包里，线要够长 |
| 自带 5V 稳压 | 部分充电宝有自动断电（小电流时） |
> ⚠️ **坑**：有些充电宝在电流小于 50mA 时会自动断电。AFS3000 只要 40mA，
> 加上主板本身功耗，总电流应该够，但**建议选带"小电流模式"的充电宝**。
### 5.2.3 三种方案对比
| 维度 | A. USB 直供 | B. 电池+升压 | C. 移动电源 |
|---|---|---|---|
| **成本** | 0 元 | 约 15~30 元 | 已有则 0 元 |
| **适合场景** | 台架调试 | **装车骑行** | 外出测试 |
| **续航** | 受限于 USB | 18650 约 5~10 小时 | 充电宝 1~2 天 |
| **改造量** | 无 | 需焊接升压模块 | 无 |
| **推荐度** | ⭐⭐⭐ 先验证 | ⭐⭐⭐⭐⭐ **最终方案** | ⭐⭐⭐⭐ 过渡方案 |
### 5.2.4 ⚠️ 五条安全红线（务必逐条确认）
| # | 红线 | 后果 |
|---|---|---|
| 1 | **AFS3000 接 VBus(5V)，不能接 3V3** | 3.3V 低于手册要求 4.8V，可能不工作 |
| 2 | **FS3000 接 3V3，绝对不能接 VBus(5V)** | 5V 直接烧毁芯片（VDD≤3.6V） |
| 3 | **升压模块输出必须先调到 5.0V 再接线** | 出厂默认可能是 12V 或更高，直接接会烧板子 |
| 4 | **所有 GND 必须共地** | 不共地会导致 I2C 通信乱码或完全不通 |
| 5 | **SDA/SCL 需外接 10K 上拉到 3.3V** | 手册图 7 明确要求；AFS3000 模块可能未内置 |
> 💡 第 5 条补充说明：手册写「R1，R2 推荐阻值为 10K」，但**上拉到 3.3V 而非 5V**——
> 因为 ESP32 的 IO 是 3.3V 逻辑，上拉到 5V 会损坏 ESP32 引脚。
> AFS3000 手册也写明「I2C 工作电平：高电平 3.3V~VDD」，所以 3.3V 上拉是合规的。

### 5.2.6 快速自检步骤（接好线后按顺序做）
| 步骤 | 操作 | 正常现象 | 异常排查 |
|---|---|---|---|
| 1 | 万用表量 AFS3000 的 VCC-GND | **5.0V ± 0.25V** | 检查升压模块输出、共地 |
| 2 | 万用表量 SDA-GND（空闲时） | **3.3V** | 检查 10K 上拉电阻 |
| 3 | 万用表量 SCL-GND（空闲时） | **3.3V** | 同上 |
| 4 | 烧录 AFS3000 版固件，看串口 | `AFS3000 OK addr=0x28` | 检查地址、接线 |
| 5 | 静止无风 | 读数 < 0.3 m/s | 检查 CRC、换算系数 |
| 6 | 用嘴吹或小风扇 | 读数明显上升 | 检查传感器方向 |
### 5.2.7 一个容易忽略的细节：AFS3000 的接口是 4P 弯插
手册第 2 页写明：
> 「插接型接口规格为 **4P 弯插**，引脚间距 **2.54mm**」
> 引脚定义：**1=SCL，2=(5V)电源，3=GND，4=SDA**
**注意引脚顺序和 FS3000 不同**！FS3000 是 SDA/SCL/VCC/GND，AFS3000 是 **SCL/VCC/GND/SDA**。
**接反会烧模块**，务必对照丝印确认。
> 如果买的是 AFS3001 底板版本，则用 **PH-4Y 接线端子**，配 UL1007-26AWG 线材，更省事。

### 7.2 L1 新增测试用例
```c
static void afs3000Tests() {
  TwoWire wire;
  AFS3000 sensor;
  float speed = -1;
  // 1. 未初始化读取失败
  assert(!sensor.readMps(speed) && speed == -1);
  // 2. 无 ACK 时 begin 失败
  wire.ack = false;
  assert(!sensor.begin(wire));
  // 3. 正常 begin
  wire.ack = true;
  assert(sensor.begin(wire));
  // 4. 零点：点数 0 → 0 m/s
  wire.setAfsCount(0);
  assert(sensor.readMps(speed) && std::abs(speed) < 0.0001);
  // 5. 换算验证：点数 2000 → 10 m/s（手册示例）
  wire.setAfsCount(2000);
  assert(sensor.readMps(speed) && std::abs(speed - 10.0f) < 0.0001);
  // 6. 满量程：点数 3000 → 15 m/s
  wire.setAfsCount(3000);
  assert(sensor.readMps(speed) && std::abs(speed - 15.0f) < 0.0001);
  // 7. 超量程钳位：点数 65535 → 15 m/s（不溢出）
  wire.setAfsCount(65535);
  assert(sensor.readMps(speed) && std::abs(speed - 15.0f) < 0.0001);
  // 8. 中间值：点数 1000 → 5 m/s
  wire.setAfsCount(1000);
  assert(sensor.readMps(speed) && std::abs(speed - 5.0f) < 0.0001);
  // 9. CRC 错误
  wire.setAfsCount(2000, /*corruptCrc=*/true);
  assert(!sensor.readMps(speed) && sensor.lastError() == AFS3000::ReadError::Checksum);
  // 10. 短帧
  wire.frame = {0};
  assert(!sensor.readMps(speed) && sensor.lastError() == AFS3000::ReadError::ShortRead);
  // 11. 连续 8 次失败熔断
  for (int i = 0; i < 8; i++) {
    wire.setAfsCount(2000, true);
    sensor.readMps(speed);
  }
  assert(!sensor.present());
  assert(!sensor.readMps(speed) && sensor.lastError() == AFS3000::ReadError::NotPresent);
  // 12. 重探测恢复
  assert(sensor.begin(wire));
  wire.setAfsCount(2000);
  assert(sensor.readMps(speed) && std::abs(speed - 10.0f) < 0.0001);
  std::cout << "PASS AFS3000: crc, scaling, clamping, error paths, offline threshold, reprobe\n";
}
```

```c
// 新增：AFS3000 帧构造（3字节 + CRC8）
void setAfsCount(uint16_t count, bool corruptCrc = false) {
  frame = {uint8_t(count >> 8), uint8_t(count), 0};
  uint8_t crc = 0x00;
  for (int i = 0; i < 2; i++) {
    crc ^= frame[i];
    for (uint8_t bit = 8; bit > 0; --bit)
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x31) : (uint8_t)(crc << 1);
  }
  frame[2] = corruptCrc ? (uint8_t)(crc ^ 0xFF) : crc;
}
```

## 九、与例程的差异说明（重要）
老大给的 STM32 例程和官方手册有**三处关键差异**，方案以**手册为准**：
| 项目 | 例程 | 官方手册 | 采用 |
|---|---|---|---|
| CRC 多项式 | `0x131` | **`0x31`** | 手册（结果等价，但更规范） |
| 换算公式 | `(raw-32000)/140`（SFM3000 规格） | **`raw × 0.005`** | **手册** |
| 通信流程 | 写命令 + 延时 + 读 | **直接读 3 字节** | **手册** |
> 例程里的 `OFFSET_FLOW 32000 / SCALE_FLOW 140` 是 **SFM3000** 的参数，**不能用于 AFS3000**。这是最容易踩的坑。
