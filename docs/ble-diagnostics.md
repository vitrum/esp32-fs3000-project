# iPhone BLE 运行日志与原始数据诊断

## 功能与范围

主固件启动后以 `AeroProbe` 名称广播 Nordic UART Service（NUS）。它使用标准 BLE GATT，不使用 iOS 不支持的通用经典蓝牙 SPP；可用 iOS 版 nRF Connect for Mobile、LightBlue 等通用 GATT APP 连接，无需自建 APP 或 MFi 配件协议。

服务和功率计、姿态传感器共用一个 NimBLE 栈：ESP32 对传感器是 Central，对手机是 Peripheral。当前连接预算为一个功率计、一个姿态传感器和一个手机。手机连接不会主动断开传感器，诊断发送限速，不另建扫描任务。

提供两类内容：

- 应用运行日志：与项目 USB 串口的应用日志内容相同，BLE 流前面增加 `[开机毫秒数]`。保留现有 USB 输出。
- 原始通知数据：按需记录收到的 CPS、FTMS、CSC、WitMotion 通知值，先记录再解析，因此也能看到长度不足、校验失败的数据。只进入内存/BLE，不从通知回调同步写 USB 或 SD。

这不是蓝牙空口、Link Layer 或 HCI 抓包，也不生成 pcap。无法看到主板未收到的数据包、重传、广播的完整空口交互，或手机系统内部的蓝牙流量。此类分析仍需独立的嗅探器/控制器跟踪工具。

## iPhone 连接步骤

1. 烧录新固件，正常开机，暂时不要播放 SD 音频。
2. 在 iPhone 安装并打开 **nRF Connect for Mobile** 或 **LightBlue**，允许蓝牙权限。直接在 APP 内扫描，不是在 iOS 系统设置里寻找串口配件。
3. 选择 `AeroProbe` 并连接。如果名称缓存不同，可用下面的服务 UUID 辨认。
4. 打开 NUS 服务，在 **TX（UUID 末段对应 `0003`）** 开启 Notify/订阅。不要只点 Read：Read 返回的是诊断状态，不是完整日志。
5. 订阅后先接收仍保留的日志，然后接收新日志。查看通知值时选择 UTF-8/Text；HEX 显示模式下看到的是整个日志文本的字节编码。
6. 如需原始传感器数据，在 **RX（`0002`）** 选择 **Write with response**，以 UTF-8/ASCII 文本写入 `RAW ON`。命令区分大小写，末尾换行可选。操作功率计/姿态传感器并复现问题。
7. 完成后写入 `RAW OFF`。在 APP 支持的日志/分享功能中保存或复制接收记录；不同版本导出能力不同，应先确认实际导出文件包含通知值，而不只是连接事件。请同时保留 TX Read 的状态和固件版本。

手机 APP 的界面、导出菜单以实际安装版本为准。持续采集建议保持 APP 在前台，避免锁屏；服务不保证 iOS 后台持续记录。

## GATT 定义

| 项目 | UUID | 属性 / 含义 |
|---|---|---|
| NUS 服务 | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` | 手机诊断 |
| RX | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` | Write with response；1–32 字节 ASCII 命令 |
| TX | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` | Notify 日志字节流；Read 状态 |

TX 通知是连续文本的任意字节分片，不是一条通知对应一行日志。按收到的顺序拼接字节后，再按 UTF-8 和换行解析；UTF-8 字符也可能被分在两次通知中。缓存回看的首段可能从一行中间开始，可丢弃首个不完整行。

## 命令

| RX 文本 | 行为 |
|---|---|
| `RAW ON` | 开始记录传感器原始通知 |
| `RAW OFF` | 停止原始通知记录，保留正常日志 |
| `PAUSE` | 暂停手机通知发送，应用日志仍写入有限缓存 |
| `RESUME` | 从当前读取位置继续发送；不自动重播全部缓存 |
| `REPLAY` | 从当前仍保留的最旧字节重新读取；如果处于 PAUSE，需另发 RESUME |
| `LIVE` | 跳过历史积压，仅接收之后的日志；如果处于 PAUSE，需另发 RESUME |
| `STATUS` | 将诊断状态写入日志；PAUSE 时可直接 Read TX 查看 |
| `HELP` | 将命令列表写入日志 |

过长写入由 GATT 属性长度限制拒绝；其余非法或含控制字符的命令会记录明确的 ERROR。无效命令不改变采集状态。此服务不接受电源、文件、功率源控制命令。

原始通知示例：

```text
[12345] [RAW] seq=17 FTMS/2AD2 len=12 off=0 hex=...
```

- `seq`：本次开机期间开启采集时收到的通知序号，不是设备空口包序号。
- `len`：原始通知长度；`off`：这一行 HEX 对应的字节偏移。
- 每行最多 32 字节 HEX；单条通知最多保留 512 字节，超出部分明确标为 TRUNCATED。
- RAW 默认关闭；手机断线、音频暂停 BLE 时自动关闭，重新连接后需手动开启。

## 缓存、限速与完整性

- 只使用独立的 **8 KiB 内存环形缓存**，不占 SD 锁、不写 SD；断电或重启即丢失。没有手机时仍缓存最近的应用日志，较早日志会被覆盖。
- 每次最多发送 `min(协商 MTU - 3, 180)` 字节；两次提交至少间隔 20 ms，由主循环推进，不保证硬实时吞吐。
- 默认 MTU 23 时，每次仅 20 字节，应用提交上限约 1 kB/s；高 MTU 也不承诺链路实际吞吐达到上限。不要求手机支持某个特定 MTU。
- 缓存覆盖了手机尚未读取的数据时，发送 `!GAP` 标记，并增加 `lost_bytes`。消息格式化过长或 RAW 超限会增加 `truncated`，不会伪装为完整记录。
- 通知提交失败时保留当前分片并重试，增加 `notify_fail`；该计数是本机提交失败，不等于全部空口丢包。
- Notify 没有应用层确认；提交成功不证明手机 APP 已保存到文件。如果需要完整的故障记录，应同时保留 USB 串口记录。开机早期日志可能在手机连接前已被覆盖。
- 不采集 ROM/bootloader、崩溃转储、第三方库直接输出到 UART/USB 的日志，也不能在主循环卡死、BLE 栈故障时继续可靠传输。

TX Read 示例：

```text
BLE-LOG v1 raw=0 paused=0 subscribed=1 lost_bytes=0 notify_fail=0 truncated=0 ring=8192
```

## 音频、重连和隐私

当前音频播放会释放整个 BLE 栈，功率计、姿态和手机连接都会断开。期间运行日志仍写入内存缓存；停止播放、BLE 栈恢复后重新广播，手机可再次连接并订阅回看。不会让诊断服务持有已销毁的 GATT 对象。

本版是开发诊断服务，**开机自动广播、未启用配对认证和链路加密**。附近设备可能连接并查看日志，日志中可能包含设备地址、SSID、GPS 坐标及运动数据。仅在受控测试环境中使用；不要把日志随意公开。若要作为面向用户的常开功能发布，应先增加本机授权开关及配对/访问控制。浏览器模拟器不提供真实 GATT 或 iOS 连接能力。

## 烧录后验收

1. iPhone 扫描、连接、订阅，检查 USB 应用日志和 BLE 文本一致（BLE 有时间前缀）。
2. 同时连接功率计、姿态、手机，开启 Wi-Fi，至少记录 30 分钟，检查 BLE 断连、GPS 溢出和 SD 丢样计数。
3. RAW ON 后检查实际支持的 CPS/FTMS/CSC/姿态 HEX 与设备通知相符；RAW OFF 后不再产生新 RAW 行。
4. PAUSE 后持续产生日志直到覆盖缓存，再 RESUME，确认出现 `!GAP` 且 `lost_bytes` 增加。
5. 测试手机断线重连、取消订阅/重新订阅、音频播放/停止，确认服务恢复、RAW 回到关闭状态。
6. 检查 iOS APP 实际保存的内容包含接收数据。主机模拟测试与编译通过不能代替上述实机验收。
